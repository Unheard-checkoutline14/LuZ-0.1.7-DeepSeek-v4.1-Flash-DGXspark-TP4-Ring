## §3 结构性结论（本报告的核心，全部 python 复算）

### 3.1 主干结论：吞吐由「单序列长度」决定，而非并发数

**固定单序列长度、变并发（列内极差）**：

| size | 列内极差 | 读法 |
|---|---:|---|
| 8192 | 4.22% | |
| 16384 | 2.63% | |
| 32768 | 2.12% | |
| **65536** | **2.13%** | Σ 负载 65,536 → 1,048,576（**16 倍**），吞吐 5792.52 → 5724.29（**−1.18%**） |
| 131072 | 3.39% | |
| 262144 | 2.87% | |
| **524288** | **1.80%** | C1→C16，5042.18 → 5038.81（**−0.07%**，几近平线） |

**⇒ 结论 A：在 8192–524288 全部档位上，并发度 C 从 1 增至 16 带来的吞吐变化 ≤ 4.22%。吞吐不是并发驱动的。**

**独立窗口佐证（关键）**：交接书基准窗自身实测 `524288-c1 = 5176.37`、`524288-c16 = 5114.61` ⇒ 行内差 **−1.19%**。
**两个相互独立的窗口，在 524288 行上都给出 ≤1.8% 的平线** ⇒ 结论 A 有跨窗复现支撑，而非单窗噪声。

**单序列长度衰减（取各 size 的 C1 列）**：

| size | C1 t/s | vs 65536-C1 |
|---|---:|---:|
| 8192 | 5360.09 | −7.47% |
| 16384 | 5498.76 | −5.07% |
| 32768 | 5772.01 | −0.35% |
| **65536** | **5792.52** | 基准（峰） |
| 131072 | 5791.05 | −0.03% |
| 262144 | 5585.68 | −3.57% |
| **524288** | **5042.18** | **−12.95%** |

**⇒ 结论 B：存在平台区 32768–131072（5772–5792 t/s）；超过 131072 后单调衰减，524288 跌 12.95%。**

### 3.2 同 Σtoken 族分析（固定总负载，换 size / 并发）

这是本矩阵信息量最高的切法——**同一总 token 量下，不同 (size, C) 组合的吞吐对比**。

| Σtoken | 组合（t/s） | 峰 | 族内极差 |
|---:|---|---|---:|
| 65,536 | 4096-C16=5033.12 ／ 8192-C8=5383.28 ／ 16384-C4=5639.30 ／ 32768-C2=5781.16 ／ **65536-C1=5792.52** | 65536-C1 | **15.09%** |
| 131,072 | 8192-C16=5326.14 ／ 16384-C8=5618.90 ／ 32768-C4=5810.26 ／ **65536-C2=5823.11** ／ 131072-C1=5791.05 | 65536-C2 | 9.33% |
| 262,144 | 16384-C16=5494.83 ／ 32768-C8=5691.90 ／ **65536-C4=5777.58** ／ 131072-C2=5671.55 ／ 262144-C1=5585.68 | 65536-C4 | 5.15% |
| 524,288 | 32768-C16=5689.80 ／ **65536-C8=5701.74** ／ 131072-C4=5620.79 ／ 262144-C2=5429.85 ／ 524288-C1=5042.18 | 65536-C8 | **13.08%** |
| 1,048,576 | **65536-C16=5724.29** ／ 131072-C8=5600.95 ／ 262144-C4=5439.91 ／ 524288-C2=4976.89 | 65536-C16 | **15.02%** |

**⇒ 结论 C（最强）：除两个最大族外，所有族的最优点都落在「单序列 = 65536」。**
**⇒ 结论 D：只要单序列保持 65536，总负载从 65,536 涨到 1,048,576（16 倍），吞吐维持在 5724–5823（−1.18%）。**

**运维含义**：调度策略应把 batch 组装目标锚定在**单序列 ≈ 64K token**，而不是「把并发堆高」。当单序列被迫变长（如 512K 长文）时，**拆成更多条更短的请求**显著优于**少数条更长的请求**：Σ=4,194,304 族中 `262144×C16`（5520.08）比 `524288×C8`（5066.58）**高 8.95%**。

### 5.2 机理（三条，均有数据支撑）

**① `decode = tok/frame ÷ ITL`，且 ITL 全程稳定。**
`itl_p50` 全域落在 **54.3–64.2 ms**（跨度仅 18%）。而 `tok/frame` 落在 **3.28–5.94**（跨度 81%）。
⇒ **全部 decode 离差来自 MTP 接受率（tok/frame），不来自引擎步进速度。**

**② coding 臂的 `min` 被「截断运行」污染。**

⇒ 截断运行的 `tok/frame`（5.07–5.36）低于全长运行（5.77），把 `min` 拉到 80.7。
**⇒ `min=80.7` 不是「最差性能」，而是「最短那次运行的加权伪影」。**

**③ 门禁 90 落在该臂的测量分布内部 ⇒ 单点判据无判别力。**
coding 五轮 **80.7 / 83.7 / 85.8 / 89.5 / 91.5**，门禁 90 嵌在分布中段。**同一条臂、同一配置，既出 FAIL 也出 PASS。**
