This repository was published on 2026-09-17/18 from a working fleet. Several documents
in it were written against **earlier build forms** and were carried into the repo
verbatim. This page is the single index of what was wrong, what it actually is, and
which files were corrected.

**How to read the rest of `docs/`:** documents dated 2026-09-11 / 09-12 / 09-13 are
**historical records** of the Form B configuration (1 M ctx · 5 M KV pool · 12 concurrent ·
fp4 indexer off). Their original values are **preserved on purpose** so the engineering
trail stays auditable; each now carries a banner at the top telling you which values are
superseded and where to read the current ones. Do not "fix" the historical numbers in place.

## Failures of process worth recording

1. **A summary table was written before its raw data existed.** The free-form DE baseline
   values (62.3 / 222.6 / 356.1 / 358.6) are present in the narrative but in no archive.
   Whatever produced them is not in the repo or on the fleet. The lesson is generic:
   *a number without a file behind it is not a measurement.*
2. **A "peak" was picked from one cell instead of searched across the matrix.** The PR
   prefill peak was quoted from 32768-C1 without comparing the other 29 cells.
3. **A composite metric was invented by adding two incommensurable quantities.** Prefill
   throughput and common-window decode throughput describe different intervals of the
   same run; summing them is meaningless.
4. **A conclusion outlived its measurement.** The gateway verdict was published from the
   pre-fix numbers and not re-derived after the fix landed the same day.
5. **Numbers were cited with a currency the data did not have.** "greedy" for a
   temperature-0.6 run; "107/108" for a run whose raw accuracy is 0.535.
6. **A hash was published whose formula was missing — and then a *second*, incompatible
   hash was published next to a formula that produced a third value.** This is worse than
   a wrong number, because a hash *looks* like proof. Two rules fall out of it:
   * a hash is only meaningful together with the **byte-exact pipeline** that produced it
     (the same 123-entry layer list hashes to `4ebef21b6aedbd70`, `bb7c2d4b38af0514`,
     `c8751accc458138c`, `38bbe8265458f328` and `0050285e87c6f408` under five
     "obviously equivalent" serializations), and
   * an identity check that reads **absent input** must fail closed. `sha256(b"")` =
     `e3b0c44298fc1c14` and `sha256(b"\n")` = `01ba4719c80b6fe9` are both well-formed
     strings that mean *"nothing was there"* — they are the same family of defect as the
     "false ABSENT / false empty" class this fleet keeps hitting.
7. **Two files in the same repository disagreed about the same identity, and neither was
   treated as authoritative.** `README` said `e541746d…` while `start.sh`'s own preflight
   comment said `4ebef21b…`. A published identifier that no working code path agrees with
   should have been a release blocker, not a documentation nit.
8. **"Does not reproduce" is not the same as "wrong", and the correction pass made this
   mistake.** Four of the five hashes this repo published for one image are *correct* —
   the same diffID list serialized four ways (space- vs newline-joined; trailing newline
   present, absent, or doubled). Rev.1.1 nevertheless labelled two of them "ghost values"
   and attributed one to a pipeline that the offline re-derivation falsifies. **Before
   calling any value a ghost, enumerate the serialization family and test it.** The real
   fault was narrower and nastier: a *quantity* was published under a name that implied a
   different *quantity* — which is exactly how four correct numbers become four
   conflicting claims about one thing.
9. **A distribution that cannot be verified offline is only as good as the publisher's
   word.** The remedy for the rows above was not one more asserted value but shipping
   `scripts/verify_release_artifact.py`, which re-derives the content identity from the
   archive alone. It was run verbatim (exit 0) before publication, and its output plus the
   full blob manifest are checked in under `data/release-artifact-20260918/`. A reader who
   does not trust this repo's numbers can now recompute them from the artifact that
   actually ships.

**Rule adopted from here on:** every number in a published table must be re-derivable
from a file in `data/` by an independent reader, and every table must carry the build
form it was measured on. **Corollary for identifiers:** every hash must ship with its
exact command, and the value used by production code is the only one that may be called
*the* identity. **Corollary for distributions:** the artifact must carry, or link, the
script that recomputes its identity — a hash the reader cannot re-derive is a claim, not
a proof.
